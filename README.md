# Filegate — 上传安检网关

转码流水线前面的准入层。它不看扩展名，只看字节：识别真实格式、发现"一份文件同时是两种
合法格式"、在展开压缩包**之前**估算代价、把图象按像素重编码以剥掉元数据和夹带，并把所有
拿不准的文件放进隔离区等人工复查。

## 为什么需要它

扩展名是客户端给的，和内容没有关系。上一个把转码机搞崩的上传，文件名是 `cover.jpg`，内容
是改了后缀的压缩炸弹。要挡住这类东西，判定必须建立在三个不信任之上：

1. **不信任文件名和 Content-Type。** 格式一律从字节重新识别。
2. **不信任容器里的声明。** ZIP 中央目录里的解压后大小是攻击者写的。网关在预算内实际
   展开每个 deflate 流来测量，声明值只用于展示。
3. **不信任"只匹配了一种格式"。** 同一份字节可以既通过 PNG 校验、又通过 ZIP 校验。
   两种都通过时，它在不同下游会被解释成不同的东西。

## 运行

```bash
npm install
npm run build:web          # 产出 web/dist，由网关同源托管
npm start                  # 默认 127.0.0.1:8787，数据在 ./data
```

开发时前端单独用 Vite 热更新：

```bash
npm run dev:server         # 网关，8787
npm run dev:web            # 管理页，5173，/api 代理到 8787
```

要求 Node ≥ 22.18（直接运行 TypeScript，无需构建步）。

## 判定结果

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| `accept` | 已识别、未触发任何规则 | 原件入库 |
| `sanitize` | 是图像，只带元数据/尾部夹带 | **重编码后的产物**入库，原件留档 |
| `quarantine` | 有无法证明安全的点 | 进隔离区，需审核人放行或拒绝 |
| `reject` | 可执行内容、路径穿越、目录自相矛盾 | 不入库，只留记录 |

拒绝与隔离都**不会**让文件进入下游。`sanitize` 的重编码失败会**降级为隔离**，不会退回原件。

## 识别与多格式检测

`src/core/detect/index.ts` 做三遍：

1. **偏移 0**：按魔数找到候选，再用该格式自己的解析器走一遍结构。只有解析成功才算
   `structural` 证据；魔数命中但结构不成立会被单独列为"未确认"，不算数。
2. **非零偏移**：单次扫描找出所有签名，逐个从该偏移起校验。这是"PNG 后面接 ZIP"、
   "HTML 后面接 JPEG"能被发现的原因。
3. **文本前缀**：按 UTF-8 合法性取前导文本，解析 HTML/XML/SVG/PHP/shebang/JSON。

**多格式（polyglot）判定规则**——两条都必须满足：

- 两侧都由真实解析器确认（`structural` 或 `textual`），仅凭魔数不算；
- 两者不是同一种容器的两种说法（`zip`/`ooxml`/`odf`/`jar` 互不构成多格式），
  也不是包含关系。

第三条很关键：PDF 里内嵌一张 JPEG、ZIP 里存一个 ZIP，是**嵌套**而不是多格式，它们由压缩包
预检处理，不应误报。`text` 被视为基底描述，永远不与其他格式构成多格式对。

## 压缩包预检

从 `src/core/archive/` 读取，绝不调用解压器。

| 容器 | 依据 | 可信度 |
| --- | --- | --- |
| ZIP | 中央目录 + **每个 deflate 成员在预算内实测展开** | 高 |
| gzip | 逐成员尾部 ISIZE；单成员另外实测 | 高 |
| tar | 512 字节头，未压缩 | 高 |
| xz | 从流尾部反解 Index（规范指定的随机访问路径） | 高 |
| bzip2 / 7z / rar | 头部无法给出大小 | **未知 → 隔离** |

对 ZIP 的处理要点：

- 声明大小**只用于展示**，判定用实测值。这同时挡住了"虚报很大"（避免误杀）和
  "少报很多"（真正的攻击）。
- 每次展开都受剩余全局预算约束；输出边到边丢弃，只保留前若干字节用于嗅探，所以
  1 GiB 的炸弹占用的内存是常数级。
- 嵌套：对每个成员的前缀嗅探内层容器，逐层下探到 `maxArchiveDepth + 1` 层为止，
  以便**证明**超限而不是猜测。
- 路径穿越、同名条目、加密条目、分卷 ZIP 都单独记一条 finding。

## 图像处理

`src/core/image/` 里，PNG/JPEG 走**解码再编码**（像素是唯一的真相来源），GIF/WebP/BMP/ICO
走**容器重写**（保留帧与图像块，丢弃注释/应用扩展/EXIF/XMP，并按容器声明的结尾截断）。
TIFF 无法在纯 JS 里安全重编码，一律隔离。

所有被接收的图像都会重编码，而不只是"脏"的——一次解码的代价换来"元数据与尾部数据一定
到不了转码器"，包括我们元数据清单里还不认识的载体。

解码前先做尺寸与像素上限判断，因此伪造 IHDR 声称 60000×60000 的 PNG 不会进入解码器。

## 时间与内存上限

`scanTimeoutMs` 是**真的中止**，不是计时器：`AbortController` 传给压缩包预检，在条目之间
检查，并且 inflater 在流中途响应。被中止的扫描一律 `quarantine`。

实测（默认上限，M 系列笔记本）：

| 输入 | 耗时 | 内存增量 |
| --- | --- | --- |
| 1 GiB 展开的 ZIP 炸弹（约 1 MiB 文件） | ~200 ms | ~35 MB |
| 60 MiB 不可压缩 ZIP | ~140 ms | ~6 MB |
| 4000×4000 PNG | ~125 ms | <1 MB |

## 默认上限

全部可用环境变量覆盖（`GET /api/health` 与"策略上限"页会显示当前生效值）。

| 项 | 默认 | 理由 |
| --- | --- | --- |
| 单文件 | 64 MiB | 再大的源素材应走离线通道 |
| 条目数 | 10 000 | 正常素材包不会更多 |
| 嵌套层数 | 2 | 套三层的压缩包几乎不存在于合法流程 |
| 累计解压 | 256 MiB | 硬性防炸弹指标 |
| 压缩比拒绝线 | 100:1 | 文本/JSON 通常 5–20:1 |
| 压缩比警戒线 | 40:1 | 高于此值但未到拒绝线，交人工 |
| 像素 | 40 MP | 覆盖 8000×5000 |
| 单边 | 12 000 px | 防超长条带图 |
| 尾部字节 | 16 | 正常编码器为 0 |
| 扫描超时 | 8 s | 超时即隔离 |
| 隔离保留 | 30 天 | 到期自动清除字节 |
| 可执行文件 | 拒绝 | 需要显式打开 |

## 隔离区

- `GET /api/records?status=quarantined` 列出待复查。
- 复查页展示：格式证据（含偏移与结束位置）、每条 finding、图像与压缩包的全部实测数值、
  本次生效的上限、以及完整审计时间线。
- 放行 / 拒绝 / 清除都需要 `X-Reviewer` 身份。服务本身不做认证——在生产中该头由前置的
  SSO 代理注入。匿名请求会被 403，而不是被当作某个默认用户。
- 放行只对 `quarantine` 且非 `reject` 的记录有效；被判拒绝的文件不能通过放行反转。
- `destroy` 删除字节、保留记录作为证据；`purge` 按保留期自动做同样的事。

## 测试

```bash
npm test                   # 82 项，覆盖核心、服务端、存储、夹具契约
npm run typecheck
node tools/generate-fixtures.ts      # 生成 fixtures/ 与 manifest.json
node tools/scan-cli.ts --dir fixtures/clean
```

夹具全部由 `tools/fixtures.ts` 用代码生成，仓库里没有二进制测试资产。每个夹具在
`tools/generate-fixtures.ts` 里声明**期望判定**，`tests/fixtures.test.ts` 逐条执行；
策略回归会表现为一个具体文件名的失败，而不是无人察觉的行为漂移。

`tests/scan.test.ts` 里有几条专门针对"声明与事实不符"的用例：

- 目录虚报 1 GiB、实际 1 KiB → 接收（不误杀）
- 目录少报 100 字节、实际 64 MiB → 隔离（真正的攻击）
- 伪造 IHDR 尺寸 → 解码前隔离
- IEND 后夹带 PHP → 清洗产物里不再包含

## 已知边界

- **不做真实解压**。7z / rar / bzip2 因此只能隔离，不能自动放行；这是刻意的取舍。
- **不递归展开所有嵌套**。每层最多下探 8 个内层容器，超出会记录
  `archive.nested_probe_capped`，但深度仍是保守估计。
- **不大包大揽认证**。审核人身份来自信任的请求头，必须由前置代理保证。
- **重编码有损**。JPEG 以质量 90 重编码，画面会有极细微变化；如果下游要求逐位一致，
  应改为"只校验不放行"。
- **SVG 不当作图像**。它是可携带脚本的文档格式，按文档处理，不做位图重编码。
